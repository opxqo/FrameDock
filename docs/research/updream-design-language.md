# updream UI 设计语言：以画布为中心的实现拆解

> 调研日期：2026-10-17。对象：[updream](https://www.updream.cn/) 的线上桌面版，重点为 `/canvas`。
> 本文是外部产品设计研究，不替代 FrameDock 的 [现行 UI 规范](../../apps/web/DESIGN.md) 和 [权威设计文档](../design.md)。

## 1. 设计语言的核心

**把画布做成一张可以无限移动的深色素材工作台：素材占据视觉主体，工具悬浮在工作台边缘，编辑能力围绕当前对象临时展开。**

它的辨识度来自六个相互配合的选择：

1. **近黑底上的内容直呈。** 图片、视频本身构成节点的主要面积，标题在外部，不用一层厚重的卡片头包住素材。
2. **固定工具，流动画布。** 全局导航、左侧工具条、底部控制条保持屏幕尺寸；节点在世界坐标里一起平移缩放。
3. **工具采用玻璃胶囊，内容采用小圆角矩形。** 工具与素材的形状、材质不同，用户容易区分“要操作什么”和“用什么操作”。
4. **操作就近出现。** 悬停暴露端口和拖动把手，选中暴露编辑条和参数面板；不把完整表单常驻在每个节点里。
5. **灰白负责日常交互，彩色负责特殊状态。** 普通选中态是灰白描边；蓝紫流光主要表达 Agent 正在工作，红色表达错误，琥珀表达过期或远程锁定。
6. **画布会随观看尺度改变信息密度。** 点阵在低缩放下淡出，媒体缩成概览，屏幕坐标里的工具保持可操作。

可用于设计沟通的关键词：**内容优先、悬浮工具、灰阶层次、轻边界、就地编辑、渐进显露、尺度感知。** 这是根据实现提炼的概括，并非网站官方命名。

## 3. 空间布局：让工具围住画布，而不是把画布塞进后台页面

### 3.1 视口中的固定区域

| 区域 | 已确认的布局 | 设计作用 |
| --- | --- | --- |
| 左上项目导航 | 独立导航组，品牌、返回、透明项目名称输入框；项目名 18px/500 | 项目信息轻量驻留，不形成厚顶栏 |
| 右上全局操作 | 桌面 `top:20px; right:20px; gap:12px` | 搜索、积分、会员、对话与素材保持距离 |
| 左侧竖工具条 | `left:20px; top:50%`，纵向居中；宽 52px，内按钮 36×36px，间隙 8px | 以胶囊岛形式组织素材、历史、剪辑等入口 |
| 左侧资源面板 | `left:77px; top:70px; bottom:20px; width:350px`，圆角 24px | 打开时贴着工具条，不改成整页导航 |
| 底部控制条 | `bottom:20px; left:50%`，水平居中；高 52px，圆角 999px | 统一管理选择/抓手、缩放、适应、连线、主题、撤销/重做 |
| 左下小地图 | `left:16px; bottom:30px`；外框 200×148px | 作为次要导航工具，与底部控制条分开 |
| 节点上下文浮层 | 编辑动作靠近节点上方，参数面板靠近节点下方 | 注意力围绕当前创作对象聚集 |

**[实测]** 调研视口为 1023×954 CSS px，初始画布缩放约 30.61%。左侧工具条实际宽 52px，底部控制条高 52px。由此可确认它们未跟随世界缩放。

**设计含义：** 减少贯穿屏幕的横线和侧栏边界，把大部分区域留给内容。四周控件的固定位置又给无限空间提供稳定参照。

依据：S4 的 `_navbarRight_1aww0_151`、`_projectNameInput_1aww0_171`、`_iconBar_vvu8o_4`、`_panelContainer_vvu8o_77`、`_toolbar_csn0r_2`、`_container_lvyx1_2`。

### 3.2 三套坐标关系

**[代码 + 实测]** 主画布是 DOM，不是将整个界面绘制到 `<canvas>`：

```text
视口 / fixed canvas-area
├── SVG 关系层：屏幕坐标，端点由节点位置换算
├── canvas-world：translate(panX, panY) + scale(zoom)
│   └── 素材节点：absolute left / top / width / height
├── 屏幕尺寸的上下文浮层：由当前节点位置计算锚点
└── 固定工具：全局导航、左侧栏、底部栏、小地图
```

节点所在世界层的 `transform-origin` 为 `0 0`。基本映射为：

```text
屏幕位置 = 世界位置 × zoom + pan
世界位置 = (屏幕位置 − pan) / zoom
```

SVG 连线层单独接收屏幕坐标，不能因为它视觉上跟着节点动，就把它当成 `canvas-world` 内的普通子元素。

**[建议]** 复用这套语言时，首先确定坐标责任。节点内容可缩放；工具条与参数输入保持屏幕尺寸；连线只转换一次坐标。把全部 UI 放进同一个缩放容器，会使输入框与点击目标缩得无法使用。

依据：S1 `applyViewDOM`、`getNodePort`、`updateAllConnectionPaths`；S3 `.canvas-world` 的 JSX；S4 `_canvasWorld_2cxx0_132`。

## 4. 画布底：不是一块永远相同的黑色背景

### 4.1 明度优先的层级

| 语义 | 暗色值 | 浅色代码值 | 使用位置 |
| --- | --- | --- | --- |
| `--bg-base` | `#0a0a0a` | `#f1f1f1` | 画布底 |
| `--bg-surface` | `#171717` | `#ffffff` | 常规表面 |
| `--bg-elevated` | `#262626` | `#ffffff` | 节点底、较实的浮层 |
| `--bg-glass` | `rgba(23,23,23,.75)` | `rgba(255,255,255,.8)` | 玻璃面板 |
| `--text-primary` | `#fafafa` | `#0a0a0a` | 标题、正文、主操作 |
| `--text-regular` | `#a1a1a1` | `#525252` | 普通次级信息 |
| `--text-secondary` | `#737373` | `#737373` | 辅助文字 |
| `--text-placeholder` | `#525252` | `#a1a1a1` | 占位提示 |
| `--stroke-regular` | 白色 10% | 黑色 8% | 工具、面板边界 |
| `--stroke-bold` | 白色 20% | 黑色 15% | 节点、较强边界 |
| `--stroke-focus` | 白色 50% | `#737373` | 聚焦、悬停轮廓 |

暗色关键值已经 computed style 核验；浅色列仅从 `[data-theme=light]` 声明读取。

`--toolbar-bg` 还有 `@supports color-mix` 覆盖：支持时暗色是 `#171717` 的 75% 透明混合，浅色是白色的 85%。不能只看前面的不透明 fallback。

**设计含义：** 用很小的明度差区分底、素材容器、工具层，避免大块彩色 UI 抢走图片和视频的注意力。主按钮大量使用浅底深字的反差，而非通用紫色主按钮。

依据：S2 `:root,[data-theme=dark]`、`[data-theme=light]`、`--toolbar-bg`。

### 4.2 点阵是尺度提示，不是纹理装饰

**[代码]** 画布背景为 `radial-gradient` 圆点，圆点色来自 `--canvas-dot-rgb`。暗色为 `54,54,54`，点半径声明为 1px。JS 动态更新点间距、偏移与透明度：

```text
起始点间距 = 48 × zoom
间距 > 64 时反复减半；间距 < 20 时反复加倍
背景偏移 = pan 对当前点间距取余
点阵透明度 = clamp((zoom − 0.3) / 0.9, 0, 1)
```

因此：

- 缩放 ≤30% 时点阵消失，概览更安静。
- 75% 缩放时透明度为 0.5；≥120% 时为 1。
- 平移时点阵跟随场景，提供移动反馈。
- 点间距经过倍频调节，避免极密或极疏。

**[实测]** 30.61% 缩放时 `--dot-size≈29.386px`、`--dot-alpha≈0.00678`。截图几乎看不到网格，但它确实存在。

依据：S1 `applyViewDOM`；S4 `_canvasArea_2cxx0_4`。

## 5. 节点：把内容当对象，而不是把对象当表单

### 5.1 节点的构成

```text
类型/来源图标 + 名称                         ← 节点外部
                 隐藏式拖动把手
          ┌──────────────────────┐
  输入端口│ 图片 / 视频 / 文本预览 │输出端口  ← 主体内容
          │ 必要时叠加状态与操作  │
          └──────────────────────┘
              参数面板（选中后）             ← 屏幕坐标浮层
```

**[代码 + 实测]** 节点绝对定位，底色 `#262626`，圆角 8px；外层 `overflow:visible`，内容层同为 8px 圆角并裁切溢出。这样标题、端口可以越出节点，而媒体仍有干净边缘。

标题在 `top:-26px; left:1px`，15px/600，最长 280px，单行省略。重命名输入框也位于节点外部，透明、无边框，维持原有空间位置。

**[代码]** 默认媒体比例 16:9，默认约 356×200 世界单位；文本默认 280×280；Agent 节点显示尺寸分支为 300×146。已有节点可有自身尺寸，不能把默认值当成所有节点的固定规格。

标题和部分状态使用 `--node-ui-scale = max(1, nodeWidth / 356)`。**这是随节点自身尺寸放大，不是按 `1 / zoom` 保持屏幕字号。** 本次概览下，15px 标题也随世界缩成约 4.59px 的视觉字号。

依据：S1 `getNodeDisplaySize`、`NODE_W`、`NODE_H`、`TEXT_NODE_SIZE$1`；S2 `_node_1q0bh_3`、`_inner_1q0bh_17`、`_typeLabel_1q0bh_182`；S3 `--node-ui-scale`。

### 5.2 状态显露顺序

| 状态 | 变化 | 意图 |
| --- | --- | --- |
| 常态 | 素材、外置标题、低对比轮廓 | 保持可浏览性 |
| 悬停 | 轮廓变亮，编辑图标、把手与适用端口出现 | 告知“这里可操作” |
| 选中 | 稳定轮廓、外圈、就地操作和参数层 | 进入编辑上下文 |
| 多选 | 相关节点使用移动光标、共同选择框/工具 | 操作集合而不是重复逐节点操作 |
| 输入关联高亮 | 有独立呼吸动画声明 | 提示当前引用对象 |
| 过期 | 上方琥珀色小标签和详情 popover | 区分内容存在与内容需要更新 |
| 失败 | 覆盖层、错误信息、重试入口 | 就地恢复 |

**[实测]** 普通节点选中的最终样式为：1px 白色 50% outline，外圈 `0 0 0 2px` 白色 10%。CSS Modules 中外圈曾声明白色 50%，但更高优先级的 `.canvas-node.selected` 生效为 10%。

**[建议]** 设计规范应写最终叠加结果。只抄某一条组件 CSS，容易把选中态做得过亮。

### 5.3 端口的细节

**[代码 + 实测]** 左右端口的基础尺寸 20×20，圆形，中心位于节点两侧的垂直中线。默认透明度 0、缩放 0.5；悬停/选中后透明度 1、缩放 1，并向外位移 18 世界单位。

伪元素 `inset:-8px` 扩展命中范围，所以可点区域大于看得见的圆。位移动画约 250ms，曲线 `cubic-bezier(.34,1.56,.64,1)` 带轻微回弹；透明度约 200ms。

端口随世界缩放：30.61% 下可见直径约 6.12px。不是固定的 20 屏幕像素。代码声明 1.5px 边框，本次环境 computed style 序列化为 1px；不要把渲染像素取整结果当作设计声明。

不同节点类型显示的端口不同，本次某些 Agent 产物只有右端口。不能总结为“所有节点都固定左右各一个”。

### 5.4 文本与视频沿用同一容器，但有各自阅读行为

**[实测]** 文本节点直接展示 Markdown 标题、列表和表格；存在“双击查看完整内容”的提示。选中文本后出现字号调整、编辑、下载，以及独立文本生成参数层。

视频节点展示媒体预览及播放、音量、截图等控制。**[代码]** 视频底部控制条在悬停或菜单打开时显露，减少常态遮挡。

**[建议]** 节点外观保持一致，内部阅读方式尊重素材类型。不要为了统一组件结构，把文本也压成图片式缩略图，或给图片加上与正文同样厚重的标题栏。

## 6. 连线：低存在感的关系提示，交互时才被强调

### 6.1 几何与视觉规格

**[代码]** 连线为 SVG 三次贝塞尔曲线，连接来源节点右侧中点与目标节点左侧中点。控制点沿水平方向拉出：

```text
dx = targetX − sourceX
handle = dx >= 0 ? dx / 2 : max(−dx / 2, 80)
控制点 = (sourceX + handle, sourceY)、(targetX − handle, targetY)
```

反向连线也保留足够弯曲空间，避免退化为一条难辨认的折返细线。这里计算发生在屏幕端点上，80 的下限不能直接理解为固定世界间距。

| 项目 | 代码/实际效果 |
| --- | --- |
| 常态颜色 | `#525252` |
| 选中最终颜色 | **[实测] `#a3a3a3`**；不是只读 token 得到的 `#737373` |
| 常态线宽 | `2.5 × zoom` CSS px |
| 选中线宽 | `3 × zoom` CSS px |
| path 悬停线宽声明 | `3.5 × zoom` CSS px；未单独验证所有命中路径下的 hover |
| 透明命中路径 | `12 × zoom` CSS px，`pointer-events:stroke` |
| 禁用引用的关系 | 虚线 `6×zoom / 5×zoom`，透明度 0.45 |
| 正在拖出的草稿线 | `2×zoom`，虚线 5/4，透明度 0.8 |

**[实测]** 30.61% 时常态线宽约 0.765px，命中路径约 3.673px。它并没有采用所有缩放下线宽恒定的方案。缩小后细线更退后，但操作也更困难。

依据：S1 `bezier`、`getNodePort`；S2 `.conn-path.selected`；S4 `_path_ikkt9_12`、`_pathMuted_ikkt9_28`、`_hitarea_ikkt9_33`。

### 6.2 显示、引用与动画是三件事

**[代码]** `showConnections` 控制一般关系是否显示；即使关闭，选中节点相关的连线仍可显示。另有特定 subagent 内部关系过滤分支。

`is_reference` 则控制这条关系是否参与引用；关闭时以更弱的虚线表达。选中连线出现引用开关，多条连线选中时有批量开关。代码中的上游素材收集会检查该字段，因此不能把它说成纯装饰线。

**但这不证明有完整 DAG 调度。** 本次没有验证整图拓扑执行、缓存、失败传播，不能从“有连线、会动”直接推出这些功能。

**[代码]** 选中相关节点或目标节点正在生成时，连线上叠加白色渐变的移动亮段：选中周期 2500ms，生成周期 4000ms，亮段长度参数为路径长度的 30%。实现通过 `requestAnimationFrame` 更新 path 的 dash 和渐变端点。

**设计含义：** 静态时表达结构，聚焦时表达关联，运行时表达方向。不要让所有线永久发光或运动。

依据：S1 `isCanvasConnectionVisible`；S3 连线组件中的 `is_reference`、`conn-comet`、`AU=.3`、`DU=4e3`、`$U=2500`。

## 7. 分组与排布：为素材添加场景，而不是增加卡片嵌套

**[实测]** 分组是节点背后的半透明色面，本次样本填充为 `rgba(200,200,200,.35)`；这属于该分组的实际配置，不能当成全部分组的唯一默认颜色。

**[代码]** 分组圆角 6px，标题位于 `top:-28px`，次级文字色，可带子节点数量。颜色选择器是五列色块网格。角部有 16×16 的透明 resize 区域。

分组/多选框的边宽用 `1.5 / zoom` 补偿世界缩放，目标是约 1.5 屏幕像素。它和普通节点、连线采用的尺度策略不同。

排布工具包含横向、纵向、网格；`computeLayout` 的公共间距为 20 世界单位，网格依据各行/列的最大尺寸排布，另有混合分组与普通节点的分支。**这个 20 只属于该排布工具，不能套给 Agent 的所有输出布局。**

依据：S2 `_rect_x0v5y_1`、`_label_x0v5y_71`；S1 `applyViewDOM`、`computeLayout`、`runLayout`。

## 8. 面板与菜单：从对象附近进入编辑

### 8.1 参数面板不等于固定右侧检查器

**[代码 + 实测]** 普通节点参数面板的基准位置在节点下方：水平对齐节点中心，距节点下边缘 16 屏幕像素。名称里出现 `rightPanel` 不代表它一定固定在屏幕右侧。

本次选中文本节点后，面板实际宽 420px、圆角 20px、背景 `rgba(23,23,23,.75)`、白色 10% 边框，20px blur + 150% saturate。外层 fixed 定位，内容没有继承画布 zoom。

**[代码]** 通用面板最小宽 420px、最大 `min(780px, 100vw−32px)`；视频分支宽度为 `min(630px, 100vw−32px)`。展开分支为 `min(1200px,90vw) × min(900px,90vh)`、12px 圆角；移动端分支为底部圆角面板、最大 70vh。后两者未进行完整交互验证。

**[实测限制]** 在本次 1023px 宽视口中，靠右节点的参数层右边缘约为 1031px，超出视口约 8px。不能声称原站所有锚定浮层都已完善处理避让。

依据：S1 `RIGHT_PANEL_GAP`、`updatePanelRightDOM`；S4 `_panel_1kysf_1`、`_panelContainer_z04aa_1`。

### 8.2 参数是一层紧凑的创作输入

**[实测]** 面板按“引用素材 → 提示词 → 类型/模型/生成”组织，模型选择采用紧凑触发器，生成使用高反差圆形按钮。引用素材不兼容时就地显示说明，而不是只在提交后通知。

**[代码]** 多个生成面板使用 32×32 圆形主按钮，浅色背景和深色图标；参数触发器常见 10px 圆角、8×10px padding。浮层的圆角更大，内部参数控件更紧凑。

选中某些 Agent 产物会显示关联会话与输入区。**[建议]** 把“内容节点”与“生成上下文”关联起来，比把每轮生成参数永久铺在画布上更省空间；但需要避免对话层遮挡当前对象。

### 8.3 右键菜单承担就地创建

**[实测]** 空白处菜单包含上传、文本/图片/视频/音频/Agent、预演台、插件、适应屏幕、粘贴。入口按素材与创作动作命名，避免暴露底层技术类型。

实际 DOM 使用 `data-canvas-ctx-menu`、`role=menuitem` 与通用 `-u-dropdown`：16px 圆角、20px blur + 150% saturate、1px 低对比边框。位置由右键屏幕坐标计算，并有边界估计逻辑。

**[建议]** 单项操作轻量呈现，复杂操作再展开面板；创建位置应对应用户右键的世界坐标。不要为了菜单完整而把生成参数也塞进第一层。

## 9. 字体、圆角与材质的分工

### 9.1 字体是工具字体，不是展示字体

**[代码 + 实测]** 全局字体栈以 `PingFang SC` 开始，后接系统字体、Segoe UI、Roboto、sans-serif；输入框、按钮、select 继承。当前页面基础字号 14px、行高 22.4px。

| 角色 | 对应规格 |
| --- | --- |
| 项目名称 | 18px / 500 |
| 节点名称 | 15px / 600，随世界缩放 |
| 常规正文/参数 | 常见 14px |
| 紧凑选择、菜单 | 常见 12–13px |
| 节点 Agent 状态标签 | 11px |
| 节点中央任务状态 | 12px，33px 高胶囊 |

不要把“所有文本采用某个统一等宽字体”当作原站设计；本次未发现这一依据。

### 9.2 圆角表达组件角色

| 角色 | 规格 | 识别效果 |
| --- | --- | --- |
| 分组底 | 6px | 接近工作区容器 |
| 素材节点 | 8px | 克制，保留图像面积 |
| 菜单 | 16px | 轻量浮层 |
| 节点参数层 | 20px | 独立编辑工具 |
| 左侧展开面板 | 24px | 大面积工具岛 |
| 竖/底工具条 | 999/9999px | 胶囊轮廓，与素材区分 |
| 端口、生成按钮 | 50% | 单点交互目标 |

不要用一个全局大圆角覆盖所有组件。`--app-radius-sm` 名字虽然叫 sm，实际值是 20px；应按用途理解，而非凭 token 名猜尺寸。

### 9.3 毛玻璃用在工具上

工具条、菜单、面板使用约 8–35px 的 backdrop blur，加细边和低强度阴影；普通素材节点不做玻璃化。暗色参数层甚至关闭了伪元素顶部高光。

**设计含义：** 表示“工具浮在内容之上”，而不是制造全屏玻璃装饰。图片始终保持自己的清晰度与色彩。

## 11. 小地图、快捷入口与缩放策略

**[实测]** 底部提供选择、Space 抓手、缩放数值、缩小/放大、适应屏幕、连线显隐、主题、撤销/重做。搜索入口标注 ⌘K，撤销/重做标注 ⌘Z/⌘Y。

**[代码]** 视口缩放夹在 0.2–5，即 20%–500%。缩放根据鼠标位置反推新的 pan，让鼠标下的世界点尽量保持不变。滚轮处理存在不同入口：有 0.9/1.1 倍率分支，也有钳制 delta 后的指数缩放分支；不能笼统称为“每次固定放大 10%”。

小地图绘图区 200×120px，加 28px 标题行；使用简化矩形而非加载所有媒体缩略图。有封面的节点和其他节点使用不同描边 token 作为填色。视口框可拖动，小地图可点击定位、可折叠。

**设计含义：** 提供“在哪里、看多大、怎么回来”三类反馈。缩放读数、适应屏幕和小地图共同降低迷路成本。

依据：S1 `setZoom`、`zoomAt`、`fitToScreen`；S3 `Xie` 小地图函数；S4 `_container_lvyx1_2`、`_vpRect_lvyx1_63`。

## 12. 可复用的实现契约

下面是根据上述行为重新表达的实现契约，**不是复制原站源码**：

```ts
type Viewport = { panX: number; panY: number; zoom: number };
type Point = { x: number; y: number };

function worldToScreen(point: Point, view: Viewport): Point {
  return {
    x: point.x * view.zoom + view.panX,
    y: point.y * view.zoom + view.panY,
  };
}

// 建议的职责拆分：
// WorldLayer: 节点坐标、素材尺寸、分组、拖动。
// RelationLayer: 屏幕端点、曲线、命中范围、引用状态。
// ContextLayer: 选中节点的上下文工具与参数面板。
// ChromeLayer: 全局导航、工具条、缩放、小地图。
// StateLayer: 选择、生成、失败、过期；不得彼此覆盖语义。
```

**[建议]** 如在 FrameDock 中借鉴，优先沿用当前 infinite-canvas 的成熟实现，按责任映射已有组件；不因原站采用 DOM+SVG 就重写整个画布，也不因文件名叫 `RightPanel` 就照搬固定右栏。

复现时可按以下顺序验收：

1. 空画布：工具固定，背景低对比，没有明显分割成后台管理页面。
2. 素材概览：图片/视频占节点主体，标题外置，边框不会比内容更抢眼。
3. hover/selected：端口、把手、外圈、编辑条逐步出现，未选中的节点保持安静。
4. pan/zoom：素材、背景、连线对齐，屏幕层工具不变小；连续缩放没有双重变换。
5. 引用与选择：禁用引用可辨认；选中节点能找到相关边；可见线和点击区域分开。
6. 面板：参数层靠近当前对象，输入保持可读，靠近视口边缘时正确避让。
7. 状态：选中、运行、失败、过期可以区分，不靠一种彩色描边承担所有意义。
8. 密集场景：缩小可看整体，放大可编辑，小地图和适应屏幕能找回内容。

这些是建议的验收项，不代表本次已经对原站逐条做完全部测试。

## 13. 借鉴到 FrameDock 时的取舍

| 值得借鉴的机制 | 与 FrameDock 当前规则的关系 |
| --- | --- |
| 内容优先、节点外置标题 | 与素材作为视觉主体的原则一致 |
| 世界层/屏幕层分离 | 可作为交互实现参考，不要求换技术栈 |
| hover 暴露端口、透明命中扩展 | 可提高整洁度和操作成功率 |
| 就地参数面板、上下文操作 | 与少打断的原则一致 |
| 固定工具位置、明确缩放与定位 | 可保持空间稳定感 |
| 运行状态采用明确视觉词汇 | FrameDock 应继续采用既定 Tally 语义 |
| 黑白胶囊、玻璃材质 | 与现行紧凑琥珀体系不同，属于待决定的视觉方向 |
| 动态点阵 | 与现行“不用点阵背景”冲突，不作为默认修改建议 |
| Agent 蓝紫流光 | 与现行“不用发光描边/彩色光晕”冲突，不自动迁移 |
| 引用开关的关系模型 | 不能替代 FrameDock 的端口与工作流执行语义 |

**建议保留机制、另行决定皮肤。** updream 最值得提炼的是“内容、操作、状态按情境分层”，单独换成黑底、胶囊和玻璃，无法得到同样的画布体验。

## 14. 需要避免的误读与原站局限

- **“没有点阵”**：低缩放时淡出，代码明确存在。
- **“所有控件随画布缩放”**：全局工具和参数面板使用屏幕坐标。
- **“节点标签保持屏幕字号”**：`node-ui-scale` 与节点宽度有关，不是 zoom 的倒数。
- **“有连线动画就有完整执行引擎”**：本次只能确认引用、选择与生成状态的前端表现。
- **“主色是紫色”**：日常交互以灰白为主；紫色主要出现在品牌/Agent 特效。
- **“设计没有渐变”**：常规画布克制，但 Agent 运行边框、扫光、空态演示和活动区都有渐变。
- **“一个 token 就能说明最终颜色”**：全局 CSS、CSS Modules、运行时 inline style 和 `@supports` 会共同决定结果。
- **“浮层永远不越界”**：本次靠右文本节点参数面板出现约 8px 越界。
- **“小控件在概览下仍易点击”**：端口和连线命中区随 zoom 缩小；30% 左右的操作精度有限。
- **“源码有响应式就代表移动端成熟”**：仅确认存在断点与底部面板分支，没有完成移动端验收。

本文记录的是上述构建版本的实现。网站发布更新后，应重新检查资源 hash、样式覆盖关系和实测状态。
