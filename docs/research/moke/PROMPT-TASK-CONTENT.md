# MOKE 创作任务提示词内容研究：从想法到可用视频

研究日期：2026-10-17。对象：[MOKE 创作提示词库](https://www.mokeaigc.ai/cinematique.html)。本文研究提示词具体教会创作者做什么、需要什么材料、能产出什么，以及怎样转为 FrameDock 的创作能力。所有嵌入方案与示例均为研究建议，未安装 Skill、未执行媒体生成、未修改业务。

## 1. 本篇覆盖范围与核心判断

本篇对已取得的公开内容数据进行 JSON 解码后阅读，未执行其 JavaScript。覆盖如下；不同标签在整站中可能交叉，不能把局部数量直接当作整站独立内容总数。

| 内容集合 | 本篇实际阅读 | 研究深度 |
|---|---:|---|
| 专业任务 `foundation` | 79 条 | 全部阅读定义、必需输入、方法、交付、验收等实质内容；统一提示正文与元数据互相核对 |
| 创意任务 `creative` | 128 条 | 全部阅读中文提示正文：动画 40、故事 24、游戏 32、声音 32 |
| 编剧 `screenwriting` | 29 条 | 全部阅读中文正文与统一约束 |
| 独立资产任务 | 12 条 | 全部阅读中英文正文；含 11 条图像资产任务与 1 条文字改写 |
| 音乐标签 | 1,196 条的分类统计；精读 15 条 | 每个分类取首、中、尾三个样本；不能据此声称完整理解每种乐器技法 |
| 配音声线 | 1,260 条的维度统计；精读 7 条 | 跨地区、年龄、性别与表达状态抽样；未试听、没有对应音频生成测试 |

**最有用的内容不是一万多条标签本身，而是三类可以串接的制作方法：故事因果与边界、画面和动作的连续性、声音及后期的实际验收。** 它们恰好补足“输入一句话→直接生成视频”中容易缺失的中间成果。

尤其要区分：专业任务 79 条明确要求产出文字方案；角色参考图等要求图像；动画、音效条目要求媒体片段；编剧任务产出剧本。它们不应全部塞进同一个媒体生成输入框。

## 2. 编剧 29 条：故事必须先成为可拍摄的因果链

这一组有三条互补维度：作品形式决定体量，题材决定冲突规则，任务决定本轮交付。比较合适的组合是“叙事短片 + 悬疑 + 场景拆解”，而不是同时调用 29 个独立编剧。

### 2.1 作品形式决定什么

| 真实条目 ID | 名称 | 内容方法 | 放进 FrameDock 前应改变什么 |
|---|---|---|---|
| `screenwriting-format-concept-short` | 概念超短片 | 一个主角、危机和核心规则，让规则通过后果显现；最后形成认知变化或不可逆选择 | 其建议体量为 1–3 分钟；按项目时长改写，保留“规则有人的代价” |
| `screenwriting-format-narrative-short` | 叙事短片 | 单一核心事件；两次不同反制逼迫主角改策略；结尾通过新行为表达变化 | 最适合第一批短视频故事流程；减少角色与场景数量 |
| `screenwriting-format-feature` | 电影长片 | 人物前史、序列结构、主副线与伏笔回收；结构框架需说明适用理由 | 不作为首批一键生成；保留长篇开发能力为后续扩展 |
| `screenwriting-format-serial` | 连续剧 | 每集结果制造下一集压力；追踪角色知识、资源、关系 | 适合系列短片，但需先有上一集状态，不从标题猜剧情 |
| `screenwriting-format-anthology` | 单元剧 | 独立冲突与结局，共享主题或世界规则；各集不能只是换人重复 | 适合系列概念短片与品牌内容主题集 |
| `screenwriting-format-vertical` | 竖屏短剧 | 开端迅速建立冲突，推进后反转并留下后续压力 | “约 3 秒冲突”仅是原条目策略；按内容选择，不能强加到科普或抒情片 |

`screenwriting-core-master` 将以上工作组织起来，但明确本轮只交付指定成果；这比“顺手包办分镜、图片和宣发”更适合可控创作。

### 2.2 11 种题材不能只当风格标签

| ID 后缀（均为 `screenwriting-genre-…`） | 创作时真正需要保留的方法 |
|---|---|
| `realism` | 资源、社会处境、时间限制落到具体行动后果，不用说教代替故事 |
| `mystery` | 分开真实事件、角色已知、观众已知；揭示必须有前置证据 |
| `horror` | 明确威胁规则与限制，逐渐减少选择空间，解法不能临时出现 |
| `comedy` | 人物认真追求目标，错误策略造成升级；笑点改变局面 |
| `romance` | 双方各有诉求与代价，关系靠行动发展，不靠一次可解释误会拖延 |
| `family` | 家庭责任、旧伤和权力关系通过付出、拒绝和选择变化 |
| `coming-of-age` | 原策略失效后产生主动新选择，用前后不同的行为证明成长 |
| `crime` | 每次行动改变风险、资源与关系，结局保留责任及后果 |
| `action` | 路线、期限、能力、障碍和接触点清楚；场面必须推进状态 |
| `speculative` | 世界规则先立，再展示社会后果；高潮不临时增加能力 |
| `period` | 分清史实、推演与虚构，时代限制真实影响人物选择 |

因此“悬疑”不能只编译为冷蓝光和压迫音乐；它首先是一种信息分配方法。视觉提示词只负责把已确定的信息安排表达出来。

### 2.3 11 个任务可以组成一条精简开发链

这些 ID 均以 `screenwriting-task-` 开头：

| 任务 | 后缀 | 输入→输出 | 接续价值 |
|---|---|---|---|
| 选题与破题 | `ideas` | 灵感、形式、时长→三个区别明显的故事方案 | 给用户选择故事发动机，不急着写满正文 |
| 故事梗概 | `synopsis` | 选中方案、锁定事实→含结局的因果梗概 | 明确结果，避免把宣传文案当故事 |
| 人物设定与弧光 | `characters` | 故事→目标、缺口、策略变化与行为证据 | 可进一步转成角色视觉与表演参考 |
| 前史与世界观 | `world` | 规则、前史→作者知识和观众可见信息 | 决定什么该进入本场画面 |
| 结构大纲 | `structure` | 故事与体量→行动、反制、代价、时长 | 控制总时长与因果节拍 |
| 场景拆解 | `scenes` | 大纲→逐场目标、转折、状态及相邻场接口 | 是从文字走向分镜最重要的中间材料 |
| 完整剧本写作 | `draft` | 已确认大纲/场景表→限定范围正文 | 只写能看、能听、能演的内容 |
| 单场改戏 | `scene-revision` | 原场、前后接口、修改边界→局部改稿 | 支持在画布中只返工一个片段 |
| 对白精修 | `dialogue` | 人物关系、目标、锁定台词→有行动功能的对白 | 区分角色说话方式，不统一变成金句 |
| 剧本诊断 | `diagnosis` | 剧本→有证据的问题、最小修法、依赖影响 | 未证明的连续性不能当作已通过 |
| 长篇续写与记忆快照 | `continuation` | 前文和状态快照→续文及新状态 | 适合连续剧和长项目，避免凭空恢复未知事实 |

**建议的最小主链**：破题→梗概→场景表→正文→诊断。人物、世界观、对白精修按需要插入，不要求所有项目走同样数量的步骤。

## 3. 创意任务 128 条：把故事转换为可检查的动作、镜头与声源

### 3.1 动画 40 条的共同骨架

12 种形式分别覆盖逐帧手绘、剪纸骨骼、风格化 3D、写实 3D、三渲二、偶定格、黏土、纸艺、水墨、像素、低多边形、动态图形。它们的区别不只在观感，而是要保持的结构不同：剪纸关注关节与层级，纸艺关注厚度和折痕，像素关注网格尺度和轮廓，水墨允许墨迹变化但不能丢失主体。

12 种表演包括步行、跑步、跳跃、搬运、预备动作、挤压拉伸、跟随、面部表演、口型、舞蹈、四足运动、双人互动。共同方法是先描述初始状态与意图，再拆主动作和恢复；按接地、抓握、肢体及道具关系检查结果。

| 真实 ID | 具体可复用方法 | 项目使用方式 |
|---|---|---|
| `creative-animation-performance-lift` | 抓握点与重量先成立，再描述腿和躯干的发力 | 视频动作描述从“用力搬箱子”改为有接触关系的动作段落 |
| `creative-animation-performance-partner` | 发起者与回应者有时间差，双方同一时刻接触同一物件 | 递物、握手、搀扶需要双角色动作表 |
| `creative-animation-performance-follow-through` | 主体先停，衣发等次级运动继续并衰减 | 不把画面所有部分都设为相同运动节奏 |
| `creative-animation-performance-lip-sync` | 对白、音频或时间码是前置输入 | 只有台词时可做配音准备，不能直接承诺口型同步 |
| `creative-animation-form-motion-graphics` | 进入、阅读停留、退出对应信息层级 | 图文动画需要留阅读时间，不能全程运动 |

8 种动态分镜组织空间建立、对话、追逐、揭示、动作节点、情绪、音乐与转场。它们将简化角色/布景用作时间和空间试验，不要求第一遍就达到最终画质。8 种循环则分别对应待机、走、跑、舞蹈、呼吸、机械、环境、接点检查。

**必须改写的默认值**：原动画常用 8 秒，动态分镜常用 10 秒。这些是模板默认，不是模型能力；FrameDock 应先依据实际片段目标和模型支持确定时长。循环还要检查位置、姿态、速度和尾部事件，只复制首尾相同画面并不等于无缝。

### 3.2 故事 24 条：12 个快速写作练习 + 12 个分镜任务

快速写作与上述编剧库有重叠，适合轻量入口：一句话、梗概、人物、关系、规则、大纲、单场、对白、冲突、伏笔、弧光、梗概转场景。它们常有“三个方案”“六场”等教学式限制。正式项目应从影片体量决定场数，保留方法而非硬套数量。

分镜任务的价值在于明确“每个镜头的职责”：

| 真实 ID | 实际内容与适用问题 |
|---|---|
| `creative-story-board-six-panel` | 将建立、目标、阻碍、行动、转折、结果变成可见节点；适合检验一个短事件是否完整 |
| `creative-story-board-coverage` | 主镜头、过肩、近景、反应提供对话剪辑覆盖，不是任意生成六张肖像 |
| `creative-story-board-blocking` | 俯视走位与相应镜头对照，先解释人物从哪来到哪去 |
| `creative-story-board-axis` | 画面左右与场景地图对应，越轴需要重建空间关系 |
| `creative-story-board-eyeline` | 察觉→目标→反应，视线高度、方向、距离一致 |
| `creative-story-board-match-action` | 交接点和物件状态跨镜连续 |
| `creative-story-board-reveal` | 在指定揭示节点前，目标不能提前泄露 |
| `creative-story-board-chase` | 路线、障碍、转角和人物距离共同决定追逐可读性 |
| `creative-story-board-emotion` | 消息到达后先反应和停顿，再选择行动 |
| `creative-story-board-montage` | 用状态变化表达时间流逝，例如物件磨损，而非随机更换画面 |
| `creative-story-board-sound-cue` | 声音先引发注意，镜头再寻找来源 |
| `creative-story-board-shot-list` | 图格用短编号与镜头表对应，长说明留在文字里 |

分镜板只能证明构图和动作节点大致可读，不能单独证明实际片长、运镜、表演和剪辑成立。建议先做独立镜头参考，再按需要输出联络表；多格图容易发生人物合并、视角重复及小字不可读。

### 3.3 游戏 32 条：优先提取资产与场景方法

8 条角色、8 条场景道具、8 条关卡、8 条交互均已读。其真正可迁移价值是用途约束：角色的装备留有活动空间、场景保留通路、地标与地图一致、损坏前后仍是同一物件。`creative-game-environment-materials` 的完好/磨损/破坏状态可以直接服务视频道具连续性；`creative-game-character-costume` 可服务服装分层设定。

关卡的路线、掩体、入口出口、楼层连接能帮助动作短片建立空间，但游戏经济、奖励、HUD、玩家重试等不是当前视频主链的优先内容。`creative-game-interaction-dialogue` 的分支与汇合适合未来互动影片，不能把这类设计文字视为已制作游戏。

### 3.4 声音 32 条：不只是“加点氛围音”

8 条环境声区分森林、雨、海岸、城市、室内、工业、夜间和天气变化；8 条拟音对应脚步、衣物、拿放、门、纸、水、装备、生物动作；8 条设计音包括打击、掠过、机关、魔法、科技、界面、转场、生物发声；8 条空间与同步处理远近、混响、隔挡、左右移动、动作同步、循环、静默、分层。

所有这些方法可以归纳为：**声源是什么→由什么动作产生→接触什么材质→距离与空间如何→何时开始及衰减→要不要与画面同步**。

`creative-sound-foley-grip` 不是泛泛“杯子音效”，而是拿起、调整握持、放回的不同接触事件。`creative-sound-space-occlusion` 强调门打开前后细节恢复，源位置不跳。`creative-sound-space-sync` 明确必须有视频或时间码，`creative-sound-space-layers` 只要求文字分层方案。

原音效常指定 6 秒，不应照搬为所有事件长度。环境底可以长于镜头，瞬态接触可能很短；制作时保留前后余量和自然尾声，再按实际画面定位。声音描述中应去除景别、镜头焦距等无关视觉参数，音乐、对白、环境底和同步音效分别准备。

## 4. 资产 12 条：区分身份、结构和风格三种锁定目标

| 真实 ID | 任务 | 应保留的要求 | 改写与验收重点 |
|---|---|---|---|
| `asset-character-reference` | 角色三视参考 | 多视图、面部细节、中性背景与柔光 | 原任务“正面去头、背面保留头部”是特殊拆分方法；不能当通用三视图默认。微笑还需嘴牙参考 |
| `asset-full-body-completion` | 全身补全 | 原姿态、可见服装材质与完整头脚 | 遮挡处属于推断，先确认补全设计，不宣称复原了不可见事实 |
| `asset-three-view-detail` | 三视图及局部 | 正、侧、背与局部细节，同尺度和安全边距 | 原文同时建议新比例又要求保持原比例，需要选一个明确优先级 |
| `asset-four-view` | 四视展示 | 两个侧面朝向相反，保持结构材质 | 要加入明确左右标签到文字说明；检查重复视角和不对称配饰 |
| `asset-t-pose` | T-Pose | 只改姿态，衣饰与风格延续 | 适合参考图；不能宣称已获得 rig 或可绑定模型 |
| `asset-a-pose` | A-Pose | 双臂斜下、腿距与身份延续 | 按角色解剖和使用目的确认姿态，避免与 T-Pose 混用 |
| `asset-style-derivation` | 同风格衍生 | 色彩、材质、线条/渲染、光影与细节密度一致 | 明确哪些继承、哪些允许创新；不把同风格误当同角色 |
| `asset-gray-model` | 灰模外观参考 | 用体块、轮廓、层次表达形体 | 产物仍是二维图像，不是带拓扑的模型；“百万面”只是观感表达 |
| `asset-architecture-isometric` | 建筑等轴测 | 去环境，保留附属结构、全体轮廓与原风格 | 隐藏立面需标记推断；不能凭一张透视图证明工程尺度正确 |
| `asset-character-breakdown` | 角色拆解 | 发型、表情、服装、道具、纹样分别展开 | 用于检查可变和不变项，拆分前后不能悄悄新增设计 |
| `asset-white-model-render` | 白模写实外观 | 结构比例固定，再赋材质、光照、环境 | AI 图像渲染不能保证几何不变；关键位置必须对照检查 |
| `asset-concrete-writing` | 画面化文案 | 用具体动作与反应承担情绪 | 可移除作者风格名，直接保留可拍摄表达的规则 |

这组最适合形成三个可复用能力：角色参考准备、场景/道具参考准备、同系列风格扩展。**三视图、表情表、灰模图是不同交付，不应合并成一个巨长提示词一次完成。** 多视图不合格时应只返工失败视角，再组装参考板。

## 5. 专业任务 79 条：最值得转成 Skill 的是制作判断

这一组的统一方法很完整：先列输入与单位，明确操作顺序，再交付计划与检查表；输入不足允许暂定但要说明假设；需要测量的结果由工具取得。它提供的是制作脑力，而不是宣称工具已执行。

| 子类及数量 | 已读内容 | 优先迁移到 FrameDock 的能力 |
|---|---|---|
| 摄影 8 | 产品、珠宝、食品、服装、建筑、室内、纪实、微距复制 | 根据材质和用途写镜头 brief；标识、尺寸、布景及可修改范围先确定 |
| 灯光 6 | 光源尺寸距离、光比、反射负补光、动机光、偏振、视点焦距 | 光源有来路、可解释阴影；避免把“柔光”误当低亮度，把焦距误当透视唯一原因 |
| 剪辑 6 | 轴线视线、动作匹配、平行交叉、J/L 切、调度节奏、声画关系 | 先有覆盖和状态，再切；每次运镜及切换服务信息变化 |
| 色彩后期 8 | 色彩链路、ACES、OCIO、HDR/SDR、镜头匹配、LUT、抠像、跟踪合成 | 先做逐镜曝光/白平衡和合成一致性检查；复杂色彩流程仅在工具与素材明确后启用 |
| 动画 6 | 时间间距、预备弧线、重叠形变、blocking、spline、polish | 先锁动作意图与接触，后做平滑和细节，不靠润色遮盖主体动作错误 |
| 3D 资产 6 | 单位预算、重拓扑、UV、PBR、LOD碰撞、绑定 | 当前保留概念与交付边界；没有模型工具时不假装能交付这些资产 |
| 声音 7 | 声源空间、房间拟音、ADR、清理混音、卷积、Ambisonics、响度循环 | 最先做声音事件表、对白可懂度、同步和实际文件验收 |
| 音乐 7 | 拍号速度、和声、织体曲式、动机、画面cue、互动音乐、分轨 | 时长、画面节点、对白避让、入出点和尾音，远比多堆曲风名关键 |
| 人声数字人 6 | 发音、韵律、多角色、口型、身份、表演协同 | 台词→发音词表→表演节拍→干声→口型；不要让音色选择吞掉表演目标 |
| 非虚构编剧 6 | 纪录片提纲、访谈、事实核验、广告、产品解释、教程 | 科普、产品与教程采用事实/素材约束，不按虚构故事任意补全 |
| 游戏系统 6 | 循环、经济、关卡、引导、状态音频、原型 | 后续互动内容能力；不作为当前视频主链必须项 |
| 设计可视化 7 | 版式、海报包装、电商、UI状态、图表、技术示意、科学 | 视频封面、解释图和信息图有用；工程/科学图保留证据和比例边界 |

## 6. 音乐与配音：词汇必须转成可听的要求

### 6.1 音乐库提供五种构件，而非 1,196 首可用配乐

分类统计：曲风 273、人声 80、语言 24、乐器技法 799、曲式 20。阅读样本显示相当多条目的正文只是一个短标签，例如短笛、闭合踩镲、前奏；其中还有“待指定”输入占位项。`promptZh` 不保证是中文自然段，部分仍为英文音乐术语。

例如 `import-music-a435ac3b44abdfab`（短笛）、`import-music-d974e061bf8f4414`（踩镲·踩镲合）、`import-music-f48f9b69afac01fb`（渐进段），三者分别描述乐器、奏法和段落功能，直接逗号相连并没有交代音乐的时间组织。

FrameDock 更值得提供的配乐方法是：

1. 明确用途：旁白背景、情绪转折、追逐、片尾，是否需要人声。
2. 指定片段总长及各段的进入退出；先有画面才能给可靠同步点。
3. 选一个主风格与少量承担不同职责的乐器；不要所有乐器都做主旋律。
4. 描述密度、音区和动态变化；对白段减少竞争，反转前可有留白。
5. 最后再给速度、拍号、调性或模型支持的参数；不把文本愿望当精确节拍结果。

样本中部分人声、结构、语言标签被来源标为 `needs-review`，例如“普通话”的英文是泛化的 `Chinese`。这种词应改成具体可理解要求，不能无审查原样批量入库。

### 6.2 配音库本质是角色选型和表演说明

1,260 条恰好覆盖三个地区分类、两种性别、21 个五岁年龄段，每个地区/性别/年龄组合十条。地区为中国、日韩、欧美，每类 420；男女各 630。**这反映模板网格的覆盖，不证明存在 1,260 种经试听区分的实际声线。**

其中 1,242 条语言/口音仍待指定，18 条是非语言发声。样本来源说明是新构造的文字设定，非已有音频。不能在产品中包装成已有可直接选用的 voice ID 或克隆声音。

精读样本 ID：`voice-cn-nv-0004-01`、`voice-cn-nv-1519-06`、`voice-cn-nv-6064-01`、`voice-cn-mn-4549-01`、`voice-jk-nv-9094-01`、`voice-euus-nv-3034-01`、`voice-euus-mn-100104-10`。

有价值的表演设计包括：愤怒可以通过咬字、重音和句尾控制表达，不必喊叫；长者可以清醒流畅，不能默认虚弱；地区标签不能推定语言；固定角色声线后，每场情绪状态变化而身份不变。台词、专名读音、语言、表演指令分别提供，并要求干声，不把背景音乐永久混入对白。

建议首批只建立少量经过试听的实用角色：自然旁白、温暖解释、清楚教程、克制戏剧、青年角色、成熟角色，再按实际 TTS 能力扩充。数量服从可辨识性与稳定性。

## 7. 三条面向 FrameDock 的创作链

以下是内容能力之间的衔接建议，不是网站功能复制方案。

### 7.1 叙事短片

创作约束→故事选题→因果梗概→人物/场景参考→场景表→镜头与动作→镜头关键图→逐镜视频→配音/拟音/配乐→连续性与交付审查。

重要接口：每场结束时人物位置、道具状态、已知信息要传给下一场；角色参考应同时约束图像和视频；音效根据实际生成动作调整。失败后定位到一个镜头或一个声音层，不把全片重新随机生成。

### 7.2 产品展示与广告

真实商品与批准主张→广告声画脚本→材质拍摄方案→产品角度与细节参考→镜头动作→口播与配乐→标识/结构/主张审查。

优先组合：`foundation-writing-brand-ad`、`foundation-photography-product`、`foundation-design-commerce`、`foundation-performance-pronunciation`。关键是保持产品本体，效果提升不能改掉包装文字、接口数量或真实功能。

### 7.3 科普与教程

来源与事实→信息层级→可展示的步骤或解释图→旁白→镜头/图文节奏→实测时长与事实复核。

优先组合：`foundation-writing-product-explainer` 或 `foundation-writing-tutorial`，加 `foundation-writing-fact-ledger` 与 `foundation-design-science`。生成图负责解释，不承担原始数据、真实实验记录或已验证操作证据的角色。

## 8. 自主撰写的改写示例

以下示例由本研究原创，仅展示如何把内容方法落实为任务；不是 MOKE 原文，不是已验证的生成结果。具体模型、时长和参考输入需按项目支持的能力配置。

### 8.1 从“感人的短片”变成可执行的故事任务

```text
项目：60 秒无对白短片，主题是一次迟到的和解。
已有材料：成年女儿、父亲、旧手表；一个维修台场景。
限制：仅两名角色，不增加回忆场景；旧手表最后必须恢复走动。
本轮只交付六个故事节拍，不生成镜头提示词。
每个节拍写明：人物想做什么、遇到什么具体阻碍、做了什么选择、
手表与人物关系发生什么变化、预计占用多少时间。
结尾用一个能被摄影机拍到的新行为表达和解。
检查父亲和女儿的知识来源；不能靠突然出现的零件或能力解决问题。
时长是计划值，等待后续动作和剪辑验证。
```

来源方法：编剧任务中的目标、反制、代价和状态接口；画面化写作中的可见动作。后续把已选节拍交给分镜，避免这一步自行扩展整套媒体生产。

### 8.2 把“女孩递杯子”拆成一个稳定的视频动作

```text
输入：已确认的双人首帧、角色参考、同一只白色陶杯；目标片段 5 秒。
画面固定为腰部以上双人中景，台面、门窗和光源位置沿用首帧。
起始：左侧角色双手握杯，右侧角色双手空置。
动作：左侧角色将杯子送向画面中央；右侧角色先伸双手接住杯体；
确认接触后左侧角色松手收回，右侧角色将杯子停在胸前。
只发生一次交接，杯子全程可见；杯柄、手指数量和人物左右关系不变。
禁止额外运镜、换场、口型说话和第二只杯子。
验收：看清持有者从左到双方再到右的变化，没有穿透或瞬间跳位。
```

来源方法：双人互动的回应延迟、动作匹配的接触顺序。若实际模型无法一次完成，应拆关键姿态与较短片段，不添加更多形容词掩盖失败。

### 8.3 声音与画面分别编写

```text
任务：为已锁定的递杯镜头准备声音，不改变视频。
先检查实际接触时点；没有视频时仅列声音事件，禁止编造时间码。
环境层：小房间平稳空气底，无车流、音乐或可辨识人声。
拟音层：袖口轻擦；双手接触杯体时仅有微弱摩擦，杯子未碰桌面则不加碰撞声。
输出：每个事件的来源、材质、同步依据、起止点及尾声处理。
先交付分层干净音频，再统一匹配房间空间；复听时检查是否遮盖重要台词。
```

这段例子刻意没有把画面中不存在的落桌动作补进来。声音库应根据素材发生的事件选择条目。

### 8.4 配乐与配音的两份任务

```text
配音：中文普通话，成年自然旁白；稳定声线，解释时清晰，结尾略放缓。
只读批准台词，停顿按语义分组，不读括号内导演说明。
专名读音用另附词表；交付干声，实测每句时长，不自动加笑声、音乐或混响。

配乐：为 30 秒产品解释视频准备无歌词器乐。
前 5 秒建立轻微好奇感；5–23 秒有旁白，保持稀疏配器与低密度旋律；
23–28 秒随结果出现小幅提升；最后 2 秒自然收束。
以轻打击承担脉动，一个键盘音色承担和声；避免持续上升音效和戏剧性爆发。
这是时间结构目标，实际音频完成后检查段落位置、对白可懂度与尾声。
```

## 9. 内容纳入的优先级与避坑

**第一批建议围绕一条片子闭环选择内容，而不是追求条目总数。** 核心是故事开发、参考资产、分镜动作、视频连续性、配音导演、声音计划与交付审查；可以先做 8–10 项能力，每项配少量明确适用任务的提示词。

**第二批再扩展内容类型**：广告产品、科普教程、风格化动画、特定声音风格、系列短片。长片、互动游戏、工程 3D、专业 HDR 或空间音频等，需要项目真实工具与交付场景后再纳入。

内容改写时至少处理这些问题：

- 硬编码数量与时长：8 秒、10 秒、6 秒、六格、六场不等于通用最佳值。
- 输入不足：角色、视频、音频、时间码、尺度和事实缺失时，不能由漂亮结果掩盖缺口。
- 提示词冲突：同一任务只能有一个明确的比例、视角和主要动作优先级。
- 结果类型错配：文字 brief、图像参考、可编辑模型、音频、最终视频必须明确区分。
- 模型无法保证：精确几何、严密同步、物理渲染、统一角色和无缝循环都必须检查实际产物。
- 风格与内容分离：同风格不意味着同人物；电影感不等于故事因果；年龄地区不等于实际声线。
- 内容权利：本文研究方法并给出原创示例，不代表第三方提示词与 Skill 已获再分发许可；正式纳入原文时需核对条目的授权。
