# T016 — 提示词里的参考图一一对应

状态：验收通过（Claude 实现并验收）
日期：2026-10-18

## 问题

画布上用“第一张图 / 长满树的那张”指代参考图不准。根因：

1. 提示框把引用存成文字“图片1”，增删连线后编号整体顺延，原来写的“图片2”会指到另一张图。
2. 编号按连线顺序，实际发送却按连线角色重排（首帧、尾帧、参考优先）；在原图上重新生成时又把原图插到最前，编号错位。参考条按连线顺序显示且不显示编号。
3. 没有翻译成模型的写法：Seedance 全系与 wan-3-0 要 `@图片N / @视频N / @音频N`，flux-3 要 `Image N`，kling-image-o3 要 `图N`。
4. 引用了已断开的图不提示，照样提交。

## 做法

- **按 ID 存引用**：提示框（图片 / 视频 / 文本 / 音频节点）插入的标签存为 `@[node:节点ID]`（与配置节点编辑器同一格式），显示为缩略图 + 当前编号；旧提示词里的“图片N”文字仍识别为标签，下次编辑时自动存成 ID。引用的节点断开或删除后显示红色“引用已失效”。（`lib/canvas/prompt-reference-tokens.ts`、`canvas-prompt-chip-input.tsx` 的 `tokenMode="id"`）
- **单一发送顺序**：提示框编号、参考条、实际发送共用同一套排序（`canvas-resource-references.ts` 的 `inputRoles` / `sortByConnectionRole` / `buildNodeMentionReferences`）；图片节点带上自身原图时，原图编为“图片1”。
- **生成时换算**：`buildNodeGenerationContext` 按发送顺序把 ID 换成“图片N / 参考视频 N / 参考音频 N”；原图前置移入上下文（`includeOwnImage`），编号与数组同处生成；引用失效直接报错，不提交、不扣费。
- **按模型翻译**：`lib/reference-syntax.ts`，在 `buildYfaiInvoke` 中执行；无文档写法的模型保留编号并在开头加一行编号说明；MJ 不改。
- **参考条**：按发送顺序排列，每张缩略图标出“图片N”。
- **运行前预检**：失效引用、提示词里的编号超过实际发送张数 → 阻止运行。
- **可读显示**：节点信息、历史版本、侧栏搜索、存素材标题、复制提示词、文本节点向下游输出时，把 ID 转回可读文字。

## 验证

- `bun test` 74 项通过（新增 8 项：token 解析与旧格式迁移、发送顺序与角色、改连线后引用不变、原图编为 1、失效引用阻止、各模型写法、编号越界、Seedance 请求体）；`pnpm typecheck` 通过。
- 免费 dry-run（不扣费）：seedance-2-0-official 的厂商请求体为“把 @图片2 … @图片1 …”，flux-3 为 “Image 2 / Image 1”，kling-image-o3 为“图2 / 图1”，gpt-image-2 为带编号说明的原文。
- 浏览器（测试画布，用完已删除）：A 普通、B 参考、C 首帧连到目标节点，参考条与 @ 菜单均显示 C=图片1、B=图片2、A=图片3；插入 A 后存为 `@[node:refA]`，缩略图标 3；断开 C 后同一标签变为 2，仍是 A；断开 A 后显示“引用已失效”，点生成被拦下并提示“本次未提交、未扣费”。
