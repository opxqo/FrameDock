# T015 — YFAI 对接加固：杜绝“已扣费却没出图”，增加核查手段

状态：验收通过（Claude 实现并验收）
方案：计划文件 `~/.claude/plans/api-delegated-hejlsberg.md`；背景见 [backend-jobs-plan.md](../design/backend-jobs-plan.md)

## 现象与根因

YFAI 控制台“调用日志”里图片任务全部成功并已扣费，画布却没拿到图，用户重试后额度被耗尽，最后出现 `wallet balance insufficient`（402，是结果不是原因）。

对照 YFAI 文档（`openapi.json`：异步任务、防重复提交、错误码）发现的缺口：

1. 图片走 `model-runtime/invoke` 也是**异步任务**（中位 1–3 分钟，高峰到 60 分钟），任务号只存在一次调用的闭包里，**从不落盘**。页面刷新、Vite 热更新整页重载、切页、休眠，都会让已付费任务的结果永久丢失。
2. 轮询只容忍 503/429；502/504、网络抖动、开发时 `tsx watch` 重启服务器都会让等待抛错，画布报失败，任务照常扣费。
3. `client_request_id` 每次随机，文档的防重复机制没用上；重试永远是新单。
4. 全程不记录 task_id / `X-Request-Id`，控制台日志与画布对不上。
5. 提示词长度被 FrameDock **自己**拦截：目录里的 `max_prompt_chars`（MJ 为 1024）只是元数据，YFAI 接口并不强制（dry-run 对 MJ 7000 字符都返回 200，请求体原样带上长提示词），画布那 4 个“提示词超过 1024 字符”错误是发送前就被我们的代码抛出的，请求根本没到 YFAI。余额检查还读错了字段（见下）。

本机核对：`/v1/skills/usage` 近 7 天 25 笔扣费共 ⚡5.16，**0 笔**能对上本地任务——都是任务系统上线前由页面直连的调用，结果需在 YFAI 控制台“作品库”手动取回。

## 做了什么

**服务端（`apps/server`）**
- YFAI 适配器：`client_request_id = 任务 id`（`idempotentSubmit`），提交结果不明时引擎用**同一个 id**自动重提（最多 5 次，不会重复扣费），重启时卡在 `submitting` 的任务也直接重提；轮询 4 秒 × 1200 次（80 分钟），502/504/网络错误只退避重试，410 才判过期；记录 `X-Request-Id`（`jobs.request_id`）；402 报“可用余额不足”；一个任务的**全部输出**都保存（`result.files[]`，图片带像素尺寸）。
- `jobs.delivered_at` + `POST /api/jobs/:id/ack` + 列表过滤 `undelivered` / `kind`：完成但没人取走的结果可查。
- 任务核查 `GET /api/jobs/audit`（`jobs/audit.ts`）：未交付、结果文件缺失、服务商已完成但本地未取（只读询问服务商）、运行过久、状态未知。
- YFAI 模拟上游 `/mock-yfai`（`mock/yfai.ts`）：可注入慢完成、502、失败、多图，用于免费端到端测试。
- 迁移 `0004`（request_id）、`0005`（delivered_at）。

**前端（`apps/web`）**
- YFAI 图片生成走服务端任务（`requestYfaiImages` → `createJob` / `watchJob`），关闭页面也不丢；完成后 `ack`。调用方签名不变。
- 回退路径（服务不可用或关闭 `serverJobs`）同样加固：提交带稳定的 `client_request_id` 并安全重试；轮询容忍瞬时错误，最长 60 分钟，只在 401/403/404/410 终止，错误信息带任务号。
- “找回”面板（`undelivered-jobs.tsx`，画布右下角）：列出已生成未交付的图片，可放到画布、下载、忽略；实时收到任务完成事件。
- 运行前预检（`lib/yfai-preflight.ts`，接入“运行”工作流）：提示词长度超过目录标注时只**提醒**、不拦截（提交前也不再抛错）；可用余额不足以覆盖本次预冻结额时才弹确认，可“仍然运行”。
- 设置 →“任务核查”：运行服务端核查，并对照 YFAI 账户流水（按 request id 匹配本地任务），列出对不上的扣费。
- 视频任务完成后也 `ack`。

**核查脚本** `pnpm verify:yfai`（`scripts/verify-yfai.ts`，只用免费接口，key 不打印）：校验 Key、余额可读、本地目录与线上目录的差异、对每个可用模型用默认参数做 dry-run。

## 验证

- 服务端 39 项测试通过（新增：幂等重提 / 同 id / 恢复、多输出与像素尺寸、402 措辞、undelivered 与 ack、重启后 submitting 重提、核查分类）。
- 前端 `bun test` 63 项通过（更新了“超时提交不重复”为“同一 id 安全重复”；新增瞬时错误轮询、4xx 不重复、预检、余额解析）。
- 端到端（模拟上游，免费）：4 个任务（多图 / 502 抖动 / 失败 / 慢）提交后 `kill -9` 服务端并重启，全部按原任务号完成；失败信息带任务号；未交付列表正确，`ack` 后消失。
- 浏览器：对测试画布，服务端完成的 2 张图在页面上实时出现“找回”按钮，点“放到画布”后生成两个图片节点；设置里“任务核查”可运行，账户流水对照给出 25 笔 / ⚡5.16。
- **核查脚本发现并修复一个真实缺陷**：实际余额字段是 `credits.available`，而代码读的是文档里的 `available_balance`，导致余额预检一直是空操作。现已两种都接受，并有单元测试。
- **真实 YFAI 图片验证（2026-10-18）**：MJ，1159 字符提示词（超过目录标注的 1024），经生图页提交 1 单（估价 ¥0.0727，冻结 ¥0.081）。YFAI 接受了长提示词（返回任务号和 request id），任务进行中刷新页面，服务端约 100 秒后完成，得到 4 张 1024×1024 图片（MJ 网格）；刷新后的页面看不到结果，于是发现生图页没有找回入口，已补上（`undelivered-jobs.tsx` 同时用于生图页，“存入生成记录”），点击后 4 张图进入生成记录并确认（ack）。
- 未验证：YFAI 音频仍走原路径；多处画布调用点里“用户点停止”后，已提交的图片任务会继续（平台没有取消接口、仍会计费），结果进入“找回”列表。
