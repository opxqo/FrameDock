# 任务卡协作流程

FrameDock 由 Claude 主导设计和验收，具体实现中的常规工作交给 Codex 完成。

## 分工

| 角色 | 职责 |
| --- | --- |
| Claude | 架构与设计文档、核心逻辑（执行引擎、数据模型）、编写任务卡、验收 |
| Codex | 按任务卡实现：工程搭建、组件接入、增删改查接口、界面拼装、配置、测试 |
| 用户 | 把任务卡交给 Codex 执行，完成后通知 Claude 验收 |

## 任务卡

- 文件命名：`T<三位编号>-<简短英文名>.md`，例如 `T001-m0-scaffold.md`。
- 状态写在卡片顶部：`待执行` → `已完成，待验收` → `验收通过` / `验收未通过`。
- 卡片内容：背景、范围、具体要求、**不要做的事**、验收标准、完成报告。

## Codex 执行规则

1. 开始前阅读根目录 `AGENTS.md`、`docs/design.md` 和对应任务卡。
2. 只做卡片范围内的事。遇到卡片没写清楚、或与设计文档冲突的地方，按最保守的方式处理，并在完成报告里写明，不要自行扩大范围。
3. 不修改 `docs/design.md` 和其他任务卡。
4. 能直接复制开源项目代码就复制（保留版权声明并登记到 `THIRD_PARTY_NOTICES.md`），其次用成熟开源库，万不得已才手写。`apps/web` 来自 infinite-canvas，修改时沿用它的结构和写法。
5. 完成后逐条自查验收标准。
6. **不要执行 git 提交**（Codex 沙箱无法写 `.git`）。改动留在工作区，由 Claude 验收通过后提交，提交信息格式：`T001: <一句话说明>`。验收标准中“提交”相关的条目由 Claude 负责。
7. 在卡片底部“完成报告”里填写：执行过的关键命令、安装的依赖及版本、与要求不一致的地方及原因、遗留问题。把卡片状态改为“已完成，待验收”。

## 验收

Claude 根据卡片的验收标准检查对应提交：运行命令、查看代码、在浏览器里确认效果。结果写在卡片的“验收记录”中；未通过时列出需要修改的具体问题，由 Codex 在同一张卡片上返工。
